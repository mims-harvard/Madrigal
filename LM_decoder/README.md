# Language model decoder analysis

Code for the language-model (LM) decoder variant of Madrigal, in which the bilinear decoder over outcome
labels is replaced by a text encoder over outcome descriptions (Supplementary Notes S4 and S5, Supplementary Fig. S10).

The pipeline reads `processed_data/drug_combination_data/DrugBank/drugbank_ddi_directed_cleaned_descriptions.tsv`
and the outcome-stratified split `processed_data/drug_combination_data/DrugBank/split_by_classes/`, both from the
[Harvard Dataverse repository](https://doi.org/10.7910/DVN/ZFTW3J), and the modality-alignment checkpoint used by
the rest of the model.

1. Raw DrugBank outcome descriptions are extracted with the first section of `process_input_data.ipynb`.
2. Augmented descriptions are generated by `text_augmentation/openai_api_batch_creation_processing.ipynb`
   (which runs `text_augmentation/openai_api_request_parallel_processor.py`) and written to
   `api_requests_multi_new.jsonl` and `api_requests_results_multi_new.jsonl`. The results file of the run used in
   the manuscript is included here, so this step can be skipped.
3. The training data are assembled by the second section of `process_input_data.ipynb`.
4. `train_ddi_mistral.py` trains the model. `lm_inference.ipynb` runs inference with a trained checkpoint.

The trained LM decoder checkpoints and their prediction scores are not distributed.
